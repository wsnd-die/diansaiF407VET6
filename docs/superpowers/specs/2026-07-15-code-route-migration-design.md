# code 工程 A/C 自动路线迁移设计

## 目标

将同级 `code` 工程中的 A/C 自动路线、导航状态机和双轮里程计移植到本 STM32F407VET6 工程，并严格使用本工程已确定的串口分配。

## 范围

- 移植新版 `app.c/.h` 的 A/C 路线应用状态机。
- 移植新版 `navigation.c/.h` 的导航状态机与四轮差速输出。
- 移植 `odometer.c/.h` 的双轮编码器位置解析与坐标更新。
- 新增 USART6 的单字节路线控制入口：`A/a` 启动 A 路线，`T/t` 停止路线。
- C 路线完成后停止四个底盘电机，并回到空闲状态。

不迁移源工程的 USART1 命令入口、USART1 调试输出、蓝牙行通信、无实现的 B 路线，以及与自动路线无关的模块。

## 串口与职责

| 串口 | 职责 | 本次迁移行为 |
| --- | --- | --- |
| USART1 | TOF 测距 | 保持 TOF 收发和中断解析，不接收路线命令。 |
| USART2 | 电机驱动 | 下发四个底盘电机速度命令，并接收地址 3、4 的位置回包。 |
| USART3 | 语音板 | 保持语音模块使用，不参与导航。 |
| UART4 | HWT101 | 保持 HWT101 的 11 字节姿态帧解析，提供 yaw。 |
| UART5 | 上位机 | 本次不分配业务。 |
| USART6 | 串口通信 | 仅接收 `A/a`、`T/t` 自动路线命令；不保留蓝牙行通信。 |

## 架构与数据流

1. USART6 中断读取一个字节，交给 `App_CommandUartRxByte()` 更新应用状态；中断中不下发电机命令。
2. 应用任务每 50 ms 调用 `App_RunCurrentMode()`。A 路线依次下发 5 个毫米路点，完成后进入 C 路线；C 路线依次下发 12 个毫米路点。
3. 导航任务每 10 ms 刷新 HWT101 校零 yaw、执行 `Navigation_TaskTick()`、轮询并解析里程计。导航依次经历空闲、目标对准、直线行进和到点航向微调。
4. 导航输出线速度与角速度，转换为四轮差速速度，向 USART2 上地址 3、2、4、1 的驱动器发送同步速度命令。
5. USART2 回包分别更新左右前轮的累计角度；一对新数据到齐后计算前进位移，用 HWT101 yaw 更新毫米坐标。

## 路线和完成规则

- A 路线保留源工程的 5 个路点：`(0,750)`、`(0,1250)`、`(0,1750)`、`(0,2250)`、`(0,0,-PI/2)`，单位为 mm，yaw 为 rad。
- C 路线保留源工程的 12 个路点，从 `(-1900,0)` 扫描到 `(-2700,0)`，单位为 mm，yaw 为 rad。
- 到达每个点先满足距离阈值 20 mm，再满足到点航向误差阈值 0.02 rad，随后才进入下一点。
- A 完成后自动开始 C；C 完成后调用 `Navigation_Stop()`，停止四个底盘电机，清除运行标志并将应用模式设为 `APP_MODE_IDLE`。
- 收到 `T/t` 时立即清除运行标志，停止导航和四个底盘电机，并回到空闲状态。

## 修改边界

- 仅修改自动路线所需的 `app`、导航、里程计、USART6 中断、初始化和空闲 FreeRTOS 任务。
- 保留 CubeMX 文件中的 `USER CODE` 边界。
- 不修改 USART1 的 TOF 中断、USART3 的语音功能、UART4 的 HWT101 解析、UART5，或现有升降/舵机任务。
- 目标工作区现有未提交修改属于用户，迁移不覆盖、不清理、不暂存这些修改。

## 验证

- 通过主机侧测试验证路线状态机：A 的 5 个路点顺序、A 到 C 的切换、C 完成后停车并空闲、`T/t` 停止。
- 静态核对六路 UART 的句柄使用和 IRQ 分发，确保路线命令只从 USART6 进入。
- 使用 Keil 工程编译，确认新增源文件加入项目且无编译或链接错误。
- 通过构建日志确认 `app.c`、`navigation.c`、`odometer.c`、`stm32f4xx_it.c` 和 `freertos.c` 被实际编译。
